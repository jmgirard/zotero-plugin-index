# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NNN>): <lesson>`. Limits: at most 25
lessons, each at most 450 bytes. Over the limits, retire, shorten, or split
lessons first. Then the lowest-ranked lesson leaves first. Rank is the newest
milestone in a lesson's provenance, and reviews mark `used M<NNN>` on the
lessons a milestone used. Corrected in place when proven false (never append a
correction).

- 2026-10-25 (M001, used M063, corrected 2026-10-30): pnpm is not installed on the maintainer's machine, so run it as `npx -y pnpm@12.15.0`. Many test files, such as the check, build, and site tests, spawn pnpm through `npm_execpath`, so run them with `pnpm test`, not bare `vitest`. The 60 s test timeout covers a first check run, which can wait 30 s to download the registry schema.
- 2026-10-25 (M007, used M060, corrected 2026-10-30): Astro inlines a small `<script>` as `type="module"` in the page, so a page test that greps for a selector string also matches the script. Match the attribute form, such as `\sdata-x="`. Since M024 the home page is the one page with scripts: a module for the search, filters, and pager, and since M060 an inline pre-paint script (corrected M015, M024).
- 2026-10-26 (M010, used M061): To plant a defect and undo it, copy the file first and restore from the copy. `git checkout <file>` restores the last commit and drops uncommitted work; once it put a committed stub back over a finished file.
- 2026-10-26 (M014, used M063): `pnpm test -- --reporter=verbose` hands `--` to Vitest, which reads the rest as a file filter and prints no test names. For per-test names, run `npx -y pnpm@12.15.0 exec vitest run --reporter=verbose` after `pnpm test`. `pnpm exec` still sets `npm_execpath`, so the spawn tests run.
- 2026-10-26 (M015, used M063): The built-in browser pane cannot screenshot or read a `file://` page. To view a built site, add a `.claude/launch.json` entry running `python3 -m http.server <port> --directory <dir>` with the site at `<dir>/zotero-plugin-index/` so Pages-path links resolve, keep the file out of git through `.git/info/exclude`, then `preview_start` it. The pane's light-scheme emulation did not apply.
- 2026-10-26 (M018, used M062, corrected M020): README, CHANGELOG, and DESIGN wrap prose near 76 columns, so `grep` for a phrase misses one split across lines. Search a joined copy: `tr '\n' ' ' < README.md | sed 's/  */ /g' | grep -o '<phrase>' | wc -l`. The joined copy is one line, so `grep -c` prints at most 1. Also strip `//` or `#` comment marks for code comments.
- 2026-10-27 (M021, used M061): An Astro template drops the line break between text and an element on the next line, so "Report that it" then `<a>Works</a>` rendered as "itWorks". Write `{" "}` at the line end. Read the built page's text, not only the template, since the site tests match markup. A test that strips tags must add no space for them, or it hides the dropped one.
- 2026-10-27 (M027, used M061): `npx -y pnpm@12.15.0 exec vitest` once hung 7 minutes inside npm before Vitest started. A test file that spawns no pnpm, such as `test/upstream.test.ts`, also runs as `./node_modules/.bin/vitest run <file>`, which starts in seconds; the spawn tests still need `pnpm test`.
- 2026-10-28 (M035, used M063): A local `dist/v1/plugins.json` can predate newer data fields, so a site built from it showed a language menu with no options. For a hand check of the real site, download the deployed `https://jmgirard.github.io/zotero-plugin-index/v1/plugins.json` into `<dir>/v1/`, then run `pnpm site --out <dir>`.
- 2026-10-27 (M030, used M062): Vitest's fake timers do not replace the timer behind `execFile`'s `timeout`, so test a git limit with a short real limit and a `PATH` shim that runs `exec sleep 600`. For a `performance.now()` limit, `vi.spyOn(performance, "now")` and move its value from `fixtureFetch`'s `onRequest` on the stalled URL, so the cut needs no real wait.
- 2026-10-28 (M036, used M062): An Edit whose old text ends before a line's end leaves the rest of that line joined to the last new line, so rewrapping README or CHANGELOG prose left lines of 94 to 129 characters. End the old text at a line break, then list long added lines: `git diff -U0 main | grep '^+' | awk 'length > 80'`.
- 2026-10-29 (M048, used M063): To check page width at several sizes in the browser pane without resizing it, load each page in a same-origin `<iframe>` of that width from one `javascript_tool` call and compare `contentDocument.documentElement.scrollWidth` with `clientWidth`. Append a 900 px `<div>` once to see the check fail.
- 2026-10-29 (M053, used M063): The built home page minifies its script and CSS: names are mangled, and `max-width: 760px` becomes `width<=760px`, so a test cannot grep for `rowShows` or match a style with `[^<]*`. To test the script, run the built text in `node:vm` with stand-in elements and timers, as `homeScript` in `test/site.test.ts` does; its stand-ins throw on a selector they do not know.
- 2026-10-29 (M054, used M062): The layout sets `overflow-wrap: anywhere` on `body`, so a narrow table header broke mid-word ("Zo ter o") at 375 px while the iframe width check still passed. Set `overflow-wrap: normal` on a table so its words break only at spaces, and look at the 375 px view in the browser pane, since the width check cannot see a broken word.
- 2026-10-30 (M057, used M059): A workflow run started by hand checks out the commit its branch held at dispatch, even while it waits queued in a concurrency group. A `Discover plugins` run dispatched while a merge run went on read the old `plugins/` and drafted 54 entries the merge then landed; its write step skipped them, but they spent the read budget. Start each backfill step only after the previous run completes.
- 2026-10-30 (M059): fflate's `zipSync` writes a zip's time from local date parts, so `mtime: "2026-01-01T00:00:00Z"` gave different bytes, and a different SHA-256, under UTC and New York time. A time built from local parts, `new Date(2026, 0, 1)`, gives the same bytes in every zone; `test/support/fixture-fetch.ts` zips fixture XPIs that way, so a golden data file can hold their SHA-256.
- 2026-10-30 (M060): An Astro page can carry a tested function in a classic `<script is:inline set:html={text}>` whose frontmatter text holds `${fn}`: the site build strips its types and comments and does not minify it, so the function must call and read nothing outside its body except built-ins, as `prePaintStyle` in `src/site/home-filter.ts` does. A site test runs the built classic script in `node:vm`.
- 2026-10-30 (M060): The browser pane records no `paint` entries, so first paint cannot be timed there. To see what a page shows before its module script runs, serve a copy of the built page with that script cut out and compare which rows have `display` other than `none` in same-origin iframes; an iframe with `sandbox="allow-same-origin"` shows the page with scripts off. A later window listener can undo the state such a copy measures.
- 2026-10-30 (M061): `upstream.repoUrl` is always GitHub's `html_url`, so a site-fixture case for an odd repo URL (a query, a GitLab host, `http:`) belongs on a failure record, whose `repoUrl` comes from a hand-typed `meta.json`; on an upstream record it builds pages GitHub never yields, such as a `…#readme/releases` link. `test/site.test.ts` lists every fixture id in home order by hand in three tests, so a new record goes into each.
- 2026-10-30 (M062): A `try` that holds both `await response.text()` and `JSON.parse` reports a body read that fails mid-transfer, such as a reset, as a body that is not JSON. Await the body before the parse's `try`, so a failed or time-cut body read reaches the outer catch with its own cause. `fixtureFetch` plants both, with `bodyError` and `stall: "body"`, as the release cases in `test/build.test.ts` do.
- 2026-10-30 (M063): `cssRules` in `test/site.test.ts` drops `@media` wrappers, so a rule inside `@media (forced-colors: active)` reads as one more rule with the same selector; to test a media block, match the layout source with a regex that names the query. Forced colors compute `background-image` to `none` unless it holds a `url()`, so a control drawn with gradients needs a forced-colors fallback, as the language menu's `appearance: auto`.
