# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NNN>): <lesson>`. Limits: at most 25
lessons, each at most 450 bytes. Over the limits, retire, shorten, or split
lessons first. Then the lowest-ranked lesson leaves first. Rank is the newest
milestone in a lesson's provenance, and reviews mark `used M<NNN>` on the
lessons a milestone used. Corrected in place when proven false (never append a
correction).

- 2026-10-25 (M001, used M017): pnpm is not installed on the maintainer's machine, so run it as `npx -y pnpm@12.15.0`. The check, add-plugin, and build tests spawn pnpm through `npm_execpath`, so run them with `pnpm test`, not bare `vitest`. A cold `npx` start once took minutes, which is why the test timeout is 60 s.
- 2026-10-25 (M001, used M009): pnpm runs a script from the package root, so a relative path argument resolves there, not where the user typed it. Resolve such arguments against `INIT_CWD`, and find repo files such as `.cache/` from `import.meta.dirname`.
- 2026-10-25 (M002, used M010): pnpm finds no script when its cwd is outside the package, so a test that runs pnpm from a temp dir passes `--dir <repo root>`. pnpm still sets `INIT_CWD` to the caller's cwd, so relative paths keep resolving there.
- 2026-10-25 (M002, used M017): To run a CLI against recorded responses, start pnpm with `NODE_OPTIONS=--import=<abs path>/test/support/preload-fixture.ts` and `ZPI_FIXTURE=<fixture>`; the preload replaces `globalThis.fetch`. Keep a failing-fixture test beside the passing one, since a passing CLI test also passes against the live network.
- 2026-10-25 (M002, used M014): Plugin-template repos keep `update.json` in a prerelease tagged `release` with no `.xpi`, and some manifests use `__MSG_name__` with `_locales/<default_locale>/messages.json`. Read real XPIs before assuming manifest shape.
- 2026-10-25 (M003, used M017): The reader turns every fetch rejection into `request-failed`, so a test of an error the reader does not name makes fetch resolve to an object that throws on read. `await` reads `then` on a resolved value, so a Proxy that throws on every property rejects at once; return `undefined` for `then`.
- 2026-10-25 (M003, used M012): Vitest's `beforeAll` uses `hookTimeout` (10 s by default), not `testTimeout`, so a hook that spawns pnpm passes its own timeout as the second argument.
- 2026-10-25 (M004, used M017): The reader's host check does DNS. Reader tests pass `{ lookup }` to `readUpstream`, a test that calls `buildData` in-process spies on `dns.promises.lookup`, and spawned CLIs get a stub from the preload. Without a stub, a test needs the network.
- 2026-10-25 (M005, used M012): fflate's `unzipSync` is synchronous, so a Vitest timeout cannot stop a test that hangs inside it. A failing-first test of a CPU-hold fix runs on until it is stopped by hand, so run it in the background and stop it with `TaskStop`.
- 2026-10-25 (M005, used M012): In a crafted zip64 test file, set only the zip64 record's total-entry field at +32. When the directory offset points at the record, fflate reads its bytes as a central-directory header, and a 0xFFFFFFFF at +24 makes `unzipSync` fail with "invalid zip data" before it loops.
- 2026-10-25 (M006, used M017): The `github-pages` environment takes deploys from `main` only. A `build.yml` dispatch on a branch checks the build job and its Pages artifact, then the deploy job fails with "not allowed to deploy to github-pages due to environment protection rules". Check the live URLs only after the merge.
- 2026-10-25 (M006, used M016): PyYAML is not installed on the maintainer's machine. To check a workflow's jobs, `if:` keys, and permissions, parse it with `ruby -ryaml -e 'YAML.load_file(".github/workflows/build.yml")'`.
- 2026-10-25 (M007, used M015): Astro inlines a small layout `<script>` as `type="module"` in every page, so a page test that greps for a selector string also matches the script. Match the attribute form, such as `\sdata-x="`. The pages carry no script since M015 (corrected M015).
- 2026-10-26 (M008, used M009): GitHub's repository search orders by best match unless `sort` is set, and that order can shift between page requests, so a paged search can miss or repeat repos. Discovery sends `sort=updated&order=desc`, and its fixture URLs carry those parameters.
- 2026-10-26 (M009, used M011): A push or pull request made with the built-in `GITHUB_TOKEN` starts no workflow run, so the bot's pull requests get no CI. The token can open a pull request only while the repo setting "Allow GitHub Actions to create and approve pull requests" is on (off until 2026-10-26). Read it with `gh api repos/<repo>/actions/permissions/workflow` (`can_approve_pull_request_reviews`).
- 2026-10-26 (M009, used M011): To build a branch commit without touching the checkout, use a temporary `GIT_INDEX_FILE` with `read-tree`, `update-index --cacheinfo`, `write-tree`, and `commit-tree`, then push the commit to the ref. `commit-tree` honors `commit.gpgSign`, so pass `--no-gpg-sign`, and set the identity with `GIT_AUTHOR_*` and `GIT_COMMITTER_*`.
- 2026-10-26 (M010, used M011): GitHub adds an issue form's `labels` only when the label exists in the repo, so create it with `gh label create` before testing a workflow keyed on it. The built-in browser pane has no GitHub sign-in, so for a live form test give the user a link prefilled with `?template=<file>.yml&<input id>=<value>`.
- 2026-10-26 (M010, used M011): Ruby's YAML is YAML 1.1, so it reads a workflow's `on:` key as the boolean `true`; read the trigger as `w[true]`, not `w["on"]`.
- 2026-10-26 (M010, used M017): To plant a defect and undo it, copy the file first and restore from the copy. `git checkout <file>` restores the last commit and drops uncommitted work; once it put a committed stub back over a finished file.
- 2026-10-26 (M011): A job's token permissions show in `gh run view --job <id> --log` under the "GITHUB_TOKEN Permissions" group; `gh api .../actions/jobs/<id>/logs` printed nothing here. `actions/upload-artifact@v7`'s `artifact-id` output is empty when that attempt uploaded nothing, so a later job gates on it rather than download an earlier attempt's artifact.
- 2026-10-26 (M012): fflate's `unzipSync` with a declared size throws "offset is out of bounds" on a stored deflate block that starts past that size, so a zip-bomb fixture made of repeated `Z_SYNC_FLUSH` blocks fails at once instead of holding the old reader. Build such a fixture as one `deflateRawSync` stream: 512 MiB of zeros at level 9 gives 521,826 bytes in about 1.25 s.
- 2026-10-26 (M014, used M017): `pnpm test -- --reporter=verbose` hands `--` to Vitest, which reads the rest as a file filter and prints no test names. For per-test names, run `npx -y pnpm@12.15.0 exec vitest run --reporter=verbose` after `pnpm test`. `pnpm exec` still sets `npm_execpath`, so the spawn tests run.
- 2026-10-26 (M014): The maintainer's python.org Python 3.14 has no CA certificates, so `urllib.request.urlopen` on an https URL fails with CERTIFICATE_VERIFY_FAILED. A live-check script reads the Pages data with `curl -sSf` through `subprocess`, and GitHub with `gh api`.
- 2026-10-26 (M015): The built-in browser pane cannot screenshot or read a `file://` page. To view a built site, add a `.claude/launch.json` entry running `python3 -m http.server <port> --directory <dir>` with the site at `<dir>/zotero-plugin-index/` so Pages-path links resolve, keep the file out of git through `.git/info/exclude`, then `preview_start` it. The pane's light-scheme emulation did not apply.
- 2026-10-26 (M017): To pin that a change keeps an output byte-identical, make the golden file from unchanged `src/` before any code edit. Node 26 runs `.ts` directly, so a scratch script can import `src/build/build.ts` and the test helpers, stub `dns.promises.lookup`, and call `buildData` with a fixed `now`. Commit the golden file in the first checkpoint, so `git diff main <sha> -- src` shows it came from the old code.
