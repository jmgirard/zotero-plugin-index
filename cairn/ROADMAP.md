## Candidates
- Catch stray and unportable entry files: `pnpm check` skips a stray file under `plugins/` with exit 0, accepts directory names that break on Windows or collide by case, passes an override reason of only zero-width characters, passes two overrides for the same field and version, and reports a UTF-8 BOM as "not valid JSON" (M001 review); `pnpm add-plugin` also writes an id that differs only by case from an existing entry or is a reserved Windows name such as CON (M002 review); an entry id with `%` or a space fails the whole `pnpm site` build with NoMatchingStaticPathFound, which also stops the data deploy (M007 review); `pnpm discover` writes ids through the same `writeEntry` (M008 review) — added 2026-10-24 — M001, M002, M007, M008
- Warn when the daily build degrades: a few hung hosts can push the build job past its 30-minute limit so no artifact is kept, since each request stops only at 60 s; add a time budget per plugin (M003 review); narrowed 2026-10-25 by M006 and 2026-10-26 by M017, which added the failure summary and the build-level warning; `pnpm discover` has no time budget either (M008 review) — added 2026-10-25 — M003, M006, M008, M017
- Retry repos refused by a download error: `pnpm discover` keeps a refused repo's record for 30 days or until its next push, and that includes `update-json-http-error` and other failures that an HTTP 429 or 503 from a download host can cause, so one bad response hides a repo; treat download HTTP errors as not recorded, which changes the state rule M008 shipped (M008 review) — added 2026-10-25 — M008
- Stop retrying a failing bot pull request: `pnpm propose` records no failure of its push or create request, so a repo whose pull request body passes GitHub's size limit fails again each run, takes one of its slots, and fails the workflow daily; record such failures under the 30-day rule (M009 review); an issue run meets the same refused request and leaves its issue open with the error (M010 review); narrowed 2026-10-26 by M011, whose read step refuses and records as `not-proposable` a repo whose branch name git refuses — added 2026-10-26 — M009, M010, M011
- Bound the time of a discover run: `discover.yml` stops at 30 minutes, and `pnpm discover` writes its state only at the end, so a run the limit kills saves the old state again and the next run reads the same first repos; its `git` and `pnpm check` spawns have no timeout; add a time budget that ends the reads early and writes the state; see "Warn when the daily build degrades" (M009 review) — added 2026-10-26 — M008, M009
- Answer issues whose run was canceled: `add-plugin-issue.yml` shares the `discover` concurrency group, and GitHub's docs say a new pending run in a group cancels the one already pending, so an issue opened while another run waits can get no comment; rerun such issues, for example from a scheduled sweep of unanswered `add-plugin` issues; an issue run can also cancel a pending scheduled `Discover plugins` run, so many issues can hold off discovery (M010, M010 review); a concurrency group per issue is no fix, since two runs could then push one branch, open two pull requests for one plugin id, leave an issue that no pull request names, or recreate a merged branch (M022 plan audit) — added 2026-10-26 — M010, M022
- Check the index at the push base: `pnpm propose` checks the index in its checkout, the commit the read job saw, but builds each commit on the newest default branch, so an entry merged during the run can be proposed again; read `plugins/` at the fetched base commit (M011 review) — added 2026-10-26 — M011
- Let old v1 schemas accept new fields: the v1 `upstream` block keeps `additionalProperties: false`, so a saved copy of the schema rejects each optional field that D-006 lets v1 gain; allowing unknown fields would let old copies accept later additions, but it changes what the schema checks; see "Keep the v1 data when v2 ships" (M013 review) — added 2026-10-26 — M013, D-007
- Count more GitHub answers as build-level: a GitHub API answer of HTTP 200 with an HTML body and a 403 from GitHub's release-asset host are not build-level, so an outage or regression that fails most records this way, but not all, still deploys (M017 review); narrowed and retitled 2026-10-26 by M018, which withholds a deploy when every record fails (D-012) (M018 review) — added 2026-10-26 — M006, M017, M018, D-011, D-012
- Keep issues open on entry-check errors: an "Add a plugin" issue run still closes the issue as not planned when `plannedProblem` throws in `draftEntry` (`unexpected-error`, such as git failing to start), though that is the bot's failure and D-011 counts `unexpected-error` as build-level; M019 left it out of scope (M019 review) — added 2026-10-26 — M019, D-011 — started M022
- Answer report issues left open: a report run that fails (the issue read, the `plugins/` read, the comment, the close, or its 10-minute timeout), a `report` label added after the issue opens, or a rerun, which comments twice, leaves a report issue open or answered twice, and nothing retries; the "Add a plugin" bot comments "could not finish" on its own failures; see "Answer issues whose run was canceled" (M020 review) — added 2026-10-27 — M020
- Keep issues open on entry write errors: an issue run closes the issue as not planned when `writeEntry` fails with `write-failed` or finds an output directory left behind (`entry-exists`), though both are the bot's fault (M022 plan audit) — added 2026-10-27 — M019, M022
- Fail builds when closed_by goes missing: `countReports` drops a report issue whose `closed_by` is absent, so if GitHub's issue list answer stops carrying the field, every count reads zero and the build still deploys, against D-013's rule that counts that cannot be read withhold the deploy; fail the issue read when an item has no `closed_by` key (M021 AC1 re-audit); a renamed or deleted `report` label gives the same result, since GitHub answers an empty list (M021 review) — added 2026-10-27 — M021, D-013
- Bound the build's report issue read: `pnpm build` lists every closed report issue on each run with no page cap, so a flood of report issues lengthens each build toward the job's 30-minute limit; see "Limit floods of report issues" (M021 review) — added 2026-10-27 — M021
- Test plugins load in headless Zotero: a CI job installs each listed plugin into a headless Zotero and records whether it loads, shown as its own source beside declared ranges and reports; promote when the data pipeline and user reports ship (both shipped, M021) — added 2026-10-24 — cairn/DESIGN.md Data sources
- Make close-issue safe on retry and races: `pnpm close-issue` skips when a bot comment already says the pull request was closed without a merge, so a run whose comment posted and whose close failed cannot be rerun (AC2 asks for that skip); a pull request reopened, or an issue closed as completed, between the read and the close is still closed as not planned; a pull request closed before the issue run's comment lands, an issue comment that names only the branch, or a renamed repo leaves the issue open; a backtick fence whose info string holds a backtick hides the `Closes` line, and one inside an HTML comment counts (M022 review) — added 2026-10-27 — M022
- [low] Limit floods of report issues: anyone can open report issues without limit, each run spends the repo's shared API budget, and a build whose issue read fails withholds the deploy (D-013) (M020 review) — added 2026-10-27 — M020, D-013
- [low] Fail issue runs with no plugins folder: `indexed` in `src/discover/discover.ts` reads entries through `listEntries`, which returns no entries for a missing `plugins/`, so an "Add a plugin" run treats the index as empty (M020 review) — added 2026-10-27 — M020
- [low] Check the restored discovery state: the discover read job restores `discovery-state-` by prefix from the default branch's cache in the same job that reads repos anyone can tag, so a job that a crafted repo took over could save a state entry that hides repos from later runs for up to 30 days; check the restored state's shape or keep the state outside the cache (M016 review) — added 2026-10-26 — M009, M016
- [low] Close the issue when its pull request closes: an issue whose bot pull request is closed without a merge stays open, though the bot's comment said it closes when that pull request merges (M010 review) — added 2026-10-26 — M010 — started M022
- [low] Block more IPv6 ranges in the host check: the M004 host check lets through ::ffff:0:0:0/96 (SIIT), 64:ff9b:1::/48 (local NAT64), 100::/64, 2001::/23 (Teredo included), fec0::/10, 3fff::/20, 5f00::/16, and 192.88.99.0/24; the translated ones reach a private address only on a NAT64 or SIIT network (M004 review) — added 2026-10-25 — M004
- [low] Order releases with bad dates safely: the reader sorts releases by `Date.parse(published_at)`, and an invalid date gives NaN, which leaves the sort order undefined, so "newest" and the stable pick can name the wrong release; GitHub gives a valid date for each published release, and no test covers it (M014 review) — added 2026-10-26 — M014
