# M066: Filter plugins by category

**Status:** done (2026-10-31, PR #349 https://github.com/jmgirard/zotero-plugin-index/pull/349)

**Goal:** Let a visitor narrow the home table to one category of related plugins, such as AI assistants or translation, and reach a category's plugins from a plugin page.

**Outcome:** `src/site/categories.ts` holds `CATEGORIES` (13 categories: slug, name, `about` text, a word pattern in English and Chinese, hand `include` and `exclude` id lists), `categories(record)`, which reads the display name and three descriptions and gives a record with no upstream facts none but its includes, and `categoryOptions`. The home page has a hidden "Category" menu after the search box, options "Name (N)" by count, ties in list order, kept in `?category=`; `rowShows` takes it as a fifth filter, rows carry `data-categories`, and `prePaintStyle` reads `category`. Each plugin page shows "Index categories" (linking to `about/#categories`) and links each category to the filtered home page; the About page's Categories section lists all 13 and links those the menu offers. The data file carries none (D-037). `cairn/references/category-ledger.md` records the hand read on the deployed data of 2026-10-30: 363 assignments, 0 wrong, 20 of 272 records with none, 8 from includes alone, 66 exclude entries; on 19 untuned plugins 2 of 27 were wrong. README, DESIGN, CHANGELOG, and `mdn-nth-child.md` describe it.

**Decisions:** D-037 (categories are the site's own grouping, labeled and linked to About, kept out of the data); the question set chose word rules over machine clustering and hand tags.
