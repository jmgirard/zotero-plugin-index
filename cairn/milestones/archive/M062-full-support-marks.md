# M062: Mark full support against released Zotero versions

**Status:** done (2026-10-30, PR #345 https://github.com/jmgirard/zotero-plugin-index/pull/345)

**Goal:** If a declared range covers every released version of a Zotero major, up to its newest release, the mark for that major reads "all".

**Outcome:** `src/build/zotero-release.ts` `readZoteroRelease` reads `https://www.zotero.org/download/client/version?channel=release` after the plugin reads, with no token and a 30 s limit (`releaseMs`), and `buildData` writes its `linux-x86_64` value as the optional top-level `zoteroRelease` of `v1/plugins.json`; the schema pattern is `^[0-9]+(\.[0-9]+)*$`, which the reader builds its own pattern from. A failed read (non-2xx, a request or body read that fails or passes the limit, a non-JSON body, a missing or other-form value) leaves the field out, returns `releaseProblem`, and the CLI prints one `::warning::cannot read the Zotero release:` line before the writes; the exit code is unchanged and the read writes no record, so it is not build-level. `src/site/version.ts` gains `LAST_RELEASES` (7.0.32, 8.0.5, 9.0.6, from the changelog pages on 2026-10-30; source note `cairn/references/zotero-changelogs.md`), `knownRelease`, and `newestRelease` (the release for its own major, else the list, else N.9); `majorSupport` and `rowMajors` take an optional `zoteroRelease`, and a range that starts after the newest release reads none. The home table, `data-zotero`, and the plugin page read it from `loadData`; the About page lists the newest release used per major and restores the 8.999 note; the legend and About say "every release of that Zotero version, up to its newest release". README, DESIGN, CHANGELOG, and build.yml's limit comment updated. On the deployed data Zotero 10 reads all for 206 plugins, against 135 under the N.9 rule.

**Decisions:** D-036 (the daily zotero.org read, written into the data; a failed read never withholds a deploy).
