# M027: Skip locale folders that hold no messages

**Status:** done (2026-10-27, PR #44 https://github.com/jmgirard/zotero-plugin-index/pull/44)

**Goal:** The `languages` list leaves out a locale folder whose files hold no messages, so Zoplicate 5.1.1, which ships 46 comment-only stub folders, lists only `en-US` and `zh-CN`.

**Outcome:** `localeLanguages` (`src/upstream/reader.ts`) inflates locale files and keeps a canonical tag only when a file in its `locale/<tag>/` or `chrome/locale/<tag>/` folders holds a message, judged by `holdsMessage`: an `.ftl` Fluent message or term line, a `.properties` line that is not blank and not a `#`/`!` comment, a `.dtd` `<!ENTITY` outside comments (an unclosed comment runs to the end), any other file type, all after a byte-order mark, extension case ignored. It reads each file from its central-directory header in the one walk (`entryAt`, `inflateEntry` split out of `zipEntry`/`unzipOne`, whose behavior is unchanged), stops reading a tag's files once one holds a message, and pushes 1 KiB of input at a time (`LOCALE_INFLATE_CHUNK_BYTES`). A file counts as holding a message without inflating when it is over 1 MiB declared or compressed, uses another compression, or would take the XPI's total past `LOCALE_MAX_BYTES` (8 MiB, each file charged the largest of declared size, compressed size, and output); so does one whose inflate fails or whose output length differs from its declared size. No locale file fails a read. README, the Unreleased CHANGELOG languages entry and reader-limits entry, the schema `languages` description, DESIGN, and the reader comments state the rule. Branch build: Zoplicate `["en-US", "zh-CN"]`, the other 27 comparable records unchanged.

**Decisions:** none. The question set kept copied folders out of scope (parked row) and granted the branch build and the dispatch of the build on main after the merge. The plan chose a per-type message rule over a size threshold, and counting an uninflated file as a message over failing the read.
