# M032: Catch blank reasons, repeat overrides, and BOMs

**Status:** done (2026-10-28, PR #59 https://github.com/jmgirard/zotero-plugin-index/pull/59)

**Goal:** `pnpm check` refuses an override reason of whitespace and format characters only and two overrides for one field and version, and it names a UTF-8 byte-order mark at the start of an entry file.

**Outcome:** In `src/check/check.ts`, `reason-not-blank` reports a reason of length 1 or more with no character outside `[\s\p{Cf}]` (JavaScript `\s` leaves out U+0085), message "overrides[i].reason holds only whitespace or format characters". The new rule `unique-override` keys each override by `JSON.stringify([field, version ?? null])`, skips a non-string field or version (left to the schema), and reports `overrides[i] has the same field <json> and <no version | version <json>> as overrides[first]`, quoted as JSON so a newline cannot print a line of its own. `readJson` returns `bom` for text that starts with U+FEFF, and `checkEntry` reports "<file> starts with a UTF-8 byte-order mark (U+FEFF): save it as UTF-8 without one" under `registry-schema` or `index-schema` as that file's only finding. `pnpm build` and discover's `indexed` still parse raw. Override tests call `checkTree` with `compileValidators({})`, so they fetch nothing and spawn no pnpm. Tests write `\u` escapes, not raw characters. README "Checking entries" and the `index.json` field list, CHANGELOG Unreleased, and DESIGN "Entry checks" state the rules.

**Decisions:** none. The plan gate chose refusing a byte-order mark over stripping it, and the `\s`/`\p{Cf}` class over a hand list; both are in git's copy of the milestone work log.
